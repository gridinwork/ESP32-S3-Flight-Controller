## 1. Что это за плата и место в системе

**Роль.** Вторая, экспериментальная реализация полётного контроллера квадрокоптера (система уровня Pixhawk 2.4.8 под ArduPilot Copter, `02_ТЗ_система.md` §1, §8). Основной коптер летает на FC-STM32 (STM32H743VIT6); FC-ESP32 — стенд для порта ArduPilot ESP32, стенд сравнения датчиков (тот же набор IMU/баро/компас, что на FC-STM32, результаты сравнимы) и Wi-Fi/ESP-NOW мост MAVLink на планшет. **На рабочий коптер не ставится, пока в порте не появятся DShot и SD-логи** (README, `04_План_сборки_коптера.md` §1).

**Почему именно ESP32-S3** (решение Олега 21.11.2026, ТЗ §0): «ESP32-S5» не существует; C3/C5/C6 одноядерные и без SDMMC; P4 без Wi-Fi и без порта ArduPilot. S3 — единственный реалистичный кандидат: 2 ядра 240 МГц, SDMMC, USB OTG, есть наработки ArduPilot. Модуль **ESP32-S3-WROOM-1-N16** (без PSRAM, C2913199): без PSRAM свободны GPIO35–37 (у R8-версий они заняты Octal PSRAM); рабочая температура −40…+105 °C против −40…+65 °C у N16R2 (`05_Проверки_прошивок.md` §1).

**С какими платами и узлами соединяется** (по схеме `fc_esp32.py` и `02_ТЗ_система.md` §2):

| Узел | Через что | Примечание |
|---|---|---|
| PWR (модуль питания, плата 03) | J5 POWER 6 pin JST-GH: +5 В, аналоговые V и I | INA226 модуля PWR — по I2C через J7/J6 (ТЗ §1: «INA226 основной», ADC — резерв) |
| GPS + внешний компас | J6 GPS1 10 pin JST-GH: UART1 + I2C0 + зуммер | один I2C на всё: IST8310 0x0E, QMC5883L 0x0D, INA226 0x40 (ТЗ §1) |
| ESC ×4 (до 7 PWM) | J12A/B/C гребёнка 2.54 мм 3×8 | PWM (LEDC/MCPWM); DShot — после слияния PR в ArduPilot |
| Приёмник DBR4 (CRSF) | J9 RC 4 pin JST-GH, UART2 | SBUS через инвертор 74LVC1G14 — выход не заведён (перемычка) |
| TLM-AIR (LoRa 433) | **физического UART нет** | только через Wi-Fi/ESP-NOW мост, либо через J9 вместо RC в стендовом режиме (ТЗ §1, README) |
| DroneCAN-устройства | J8 CAN 4 pin JST-GH, TWAI + TJA1051T/3 | CAN в v1 (решение Олега); драйвера CAN в порте ArduPilot ESP32 не найдено (`B_esp32_fc.md` §3) |
| ПК / планшет | USB-C J2 (OTG CDC, прошивка), Wi-Fi (MAVLink UDP/TCP) | |
| Отладка | J13 UART0 4 pin 2.54 мм, кнопки BOOT/RESET | |

**Ограничения порта ArduPilot ESP32** (ТЗ §0, `B_esp32_fc.md` §2.1, §3): порт официально экспериментальный, на S3 — сторонние форки; DShot только в открытых PR #33555/#33632/#33633 (июль 2026, проверено сниффером, не на моторе, не слиты); SD-логи не работали; CAN не поддержан; UART всего 3 (один — консоль); детерминизм хуже из-за Wi-Fi-стека на том же SoC; на PWM-ESC квадрокоптер летает (Stabilize/AltHold/Loiter), MAVLink по Wi-Fi работает «из коробки». Паритета с Pixhawk 2.4.8 нет. Запасной план (ТЗ §4): своя прошивка на ESP-IDF/Arduino — Wi-Fi/ESP-NOW мост телеметрии и стенд датчиков; всё железо для этого на плате есть.

## 3. Состав и принцип работы по узлам

Все обозначения, цепи и выводы — из `fc_esp32.py` и `Netlist.json`. LCSC-номера — из `common.py` / `_BOM.xlsx`.

### 3.1 Модуль ESP32-S3-WROOM-1-N16 (U1, C2913199)

Модуль 25.5 × 18 мм, 41 вывод, 16 МБ флэш, без PSRAM, Wi-Fi 2.4 ГГц + BLE 5, PCB-антенна на модуле. Питание 3.3 В с цепи `+3V3` (вывод 2), GND — выводы 1, 40, 41. Развязка у вывода 3V3: C1 10 мкФ + C2 100 нФ (0402).

- **EN** (вывод 3, цепь `ESP_EN`): R1 10 кОм на +3V3, C3 1 мкФ на GND, кнопка SW1 «RESET» на GND.
- **GPIO0** (вывод 27, цепь `BOOT`): R2 10 кОм на +3V3, кнопка SW2 «BOOT» на GND. Strapping: низкий уровень при сбросе = режим загрузки.
- **GPIO46** (вывод 16, цепь `PWM7`): strapping, R11 10 кОм на GND; по Pinmap §1 использовать только как выход, активный после старта.
- **GPIO3 и GPIO45** — не подключены (выводы 15 и 26 модуля без цепи): strapping JTAG-источник и VDD_SPI (Pinmap §1, README).
- **GPIO33/34 у модуля не выведены** (41 контакт; наружу идут IO0–IO21, IO35–IO48 — `05_Проверки_прошивок.md` §6.1), отсюда перенос M4/M5 (см. §6, §9).
- **USB**: GPIO19/20 (выводы 13/14) — `USB_DN`/`USB_DP`, встроенный USB OTG (CDC + прошивка).
- **UART0**: TXD0/RXD0 (выводы 37/36) — `UART0_TX`/`UART0_RX` на отладочную гребёнку J13; консоль ArduPilot.

В BOM-экспорте LCSC у модуля указан диапазон −40…+85 °C, в README/`05` §1 по даташиту Espressif для N16 — −40…+105 °C; расхождение атрибутов LCSC и даташита, на схему не влияет.

### 3.2 IMU1 — IIM-42652 (U2, C2988404), SPI

6-осевой IMU TDK InvenSense, LGA-14. Питание VDD и VDDIO от **`+3V3S`** (отдельный LDO датчиков), развязка C4 100 нФ + C5 2.2 мкФ. Интерфейс SPI (FSPI): `AP_SCLK` → `SPI_SCK` (GPIO4), `AP_SDI` → `SPI_MOSI` (GPIO5), `AP_SDO` → `SPI_MISO` (GPIO6), `AP_CS` → `IMU1_CS` (GPIO7), `INT1` → `IMU1_INT` (GPIO10, EXTI). Остальные 6 выводов (в Netlist 2, 3, 7, 9, 10, 11) не подключены. В ArduPilot драйвер Invensensev3 знает `INV3_ID_IIM42652 0x6f` (`05` §3, проверено по master для FC-STM32).

### 3.3 IMU2 — BMI270 (U3, C2836813), SPI

6-осевой IMU Bosch, LGA-14. VDD, VDDIO — `+3V3S`, развязка C6, C7 по 100 нФ; GND и GNDIO — GND. SPI: `SCX` → `SPI_SCK`, `SDX` → `SPI_MOSI`, `SDO` → `SPI_MISO`, `CSB` → `IMU2_CS` (GPIO8). **Выводы INT не подключены** — вторым INT IMU пожертвовали ради бюджета GPIO (Pinmap §2). Не подключены 6 выводов (в Netlist 2, 3, 4, 9, 10, 11).

### 3.4 Барометр — MS5611-01BA03 (U4, C15639), SPI

QFN-8. VDD — `+3V3S`, развязка C8 100 нФ. `PS` на GND (режим SPI), `CSB` → `BARO_CS` (GPIO9), `SDO` → `SPI_MISO`, `SDI/SDA` → `SPI_MOSI`, `SCLK` → `SPI_SCK`. **В Netlist выводы 4 и 5 U4 оба на цепи `BARO_CS`** (в `fc_esp32.py` CSB задан один раз) — проверить символ C15639 и даташит: какой из них CSB, что на втором (см. §9).

Три датчика на одной шине FSPI (SCK/MOSI/MISO — GPIO4/5/6) с тремя CS (GPIO7/8/9); Pinmap §2: 10–16 МГц.

### 3.5 Компас — IST8310 (U5, C2683055), I2C

LGA-16. AVDD, DVDD — `+3V3S`, развязка C9 100 нФ; `C1` → C10 220 нФ на GND (цепь `IST_C1`). `RSTN` подтянут к +3V3S (сброс не управляется). Адресные входы: `CAD1` = +3V3S, `CAD0` = GND; ожидаемый адрес 0x0E (ТЗ §1) — соответствие комбинации CAD1/CAD0 адресу проверить по даташиту. `SDA`/`SCL` → `I2C_SDA`/`I2C_SCL` (GPIO11/12). Не подключены выводы 3, 4, 7, 8, 12, 15 (Netlist).

Шина I2C0 общая: IST8310 на плате + разъёмы J6 (GPS: внешний компас) и J7 (I2C: INA226 модуля PWR). Подтяжки R3, R4 2.2 кОм к `+3V3` (не к +3V3S). ESD — D5 PRTR5V0U2X (C330092): IO1 = SCL, IO2 = SDA, VCC = +3V3. 400 кГц (Pinmap §2).

### 3.6 microSD — TF-01A (J1, C91145), SDMMC 1 бит

Разъём microSD (push-push, 13 выводов в Netlist). Подключено: `CMD` → `SD_CMD` (GPIO39), `CLK` → `SD_CLK` (GPIO38), `DAT0` → `SD_D0` (GPIO40), `VDD` → +3V3, VSS/GND и выводы корпуса 10–13 → GND. DAT1, DAT2, CD/DAT3 и детектор карты не подключены (1-битный режим ради бюджета GPIO, ТЗ §1). Подтяжки R7 (SD_CMD) и R8 (SD_D0) 10 кОм 0402 к +3V3; C16 10 мкФ на +3V3 у разъёма. По расстановке v2 J1, R7, R8, C16 — **на нижней стороне**, карта вставляется через левую кромку под J5 (README). В порте ArduPilot ESP32 SD-логи не работали (ТЗ §0) — железо под них есть.

### 3.7 USB-C (J2, TYPE-C-31-M-12, C165948)

Разъём 16 pin. VBUS (A4/B9, B4/A9) → цепь `VBUS` → диод D3 SS34 → `+5V`. CC1 (A5) → R5 5.1 кОм на GND, CC2 (B5) → R6 5.1 кОм на GND (устройство-потребитель). D+ (A6/B6) → `USB_DP_C`, D− (A7/B7) → `USB_DN_C`, SBU (A8/B8) не подключены, корпус/EH → GND. ESD-матрица D1 USBLC6-2SC6 (C7519): 1 = USB_DN_C, 3 = USB_DP_C, 4 = `USB_DP`, 6 = `USB_DN`, 5 = VBUS, 2 = GND — после неё линии идут на GPIO20/GPIO19 модуля. Последовательных резисторов на D± нет. Ширины дорожек USB в правилах трассировки 0.2 мм (`BOARD["route"]`).

### 3.8 CAN — TJA1051T/3 (U6, C38695), TWAI

Трансивер SOIC-8: `TXD` ← `CAN_TX` (GPIO41), `RXD` → `CAN_RX` (GPIO42), VCC = +5V (развязка C17 100 нФ), VIO = +3V3 (уровни под 3.3-вольтовый МК), `S` = GND (нормальный режим, без тихого). CANH/CANL → цепи `CAN_H`/`CAN_L` → J8. Терминатор R9 120 Ом **впаян постоянно** между CAN_H и CAN_L (по ТЗ системы F14 — «перемычкой»; `05` §6 отмечает то же для FC-STM32). Драйвера CAN в порте ArduPilot ESP32 не найдено (`B_esp32_fc.md` §3) — узел для своей прошивки (TWAI) или будущего порта.

### 3.9 Питание (U7, U8, D2–D4) — подробно в §4.

### 3.10 RC-вход (J9, U10, R12, R13)

J9 (JST-GH 4 pin): 1 = +5V, 2 = `RC_RX_IN`, 3 = `RC_TX_OUT`, 4 = GND. `RC_RX_IN` → R12 100 Ом → `RC_RX` (GPIO16, UART2 RX); `RC_TX` (GPIO15, UART2 TX) → R13 100 Ом → `RC_TX_OUT`. CRSF (DBR4, полудуплекс с телеметрией обратно) идёт напрямую. Инвертор U10 SN74LVC1G14 (C7835, VCC = +3V3): вход A = `RC_RX_IN`, выход Y = `RC_RX_INV` — **цепь RC_RX_INV ни к чему не подключена** (в Netlist единственный вывод). Для SBUS нужна перемычка RC_RX_INV → RC_RX (README, `05` §6.1); как именно (и отключение R12) — не задано в документах. ESD на J9 в схеме нет.

### 3.11 ESC/серво-выходы (J12A/B/C)

Три гребёнки 1×8 2.54 мм (C9900015386; в BOM-экспорте — «排母», т.е. **гнездо (female)**, посадочное место `HDR-TH_8P-P2.54-V-F`; ESC-кабели обычно с гнёздами — тип разъёма проверить перед заказом). J12A — сигналы: 1..7 = `PWM1`..`PWM7`, 8 — не подключён (M8 в этой версии нет). J12B — все 8 выводов на `+5V_SERVO`; J12C — все 8 на GND. Цепь `+5V_SERVO` **не связана** с `+5V` платы (ТЗ системы F16: серво-рейка только GND и защитный диод); защитного диода/стабилитрона на `+5V_SERVO` в схеме нет. PWM-выходы: GPIO17, 18, 21, 35, 36, 37, 46 (LEDC/MCPWM; DShot по RMT, когда появится в ArduPilot). 7 выходов: 4 мотора + 3 AUX (Pinmap, правка 23.11).

### 3.12 Зуммер (Q1, R10) и RGB-светодиод (U9)

- Зуммер: GPIO47 `BUZZER` → затвор Q1 2N7002 (C8545), R10 10 кОм затвор–GND; сток → цепь `BUZZ_N` → J6 вывод 9 (как BUZZER− в стандарте Pixhawk GPS1). Второй вывод зуммера (плюс 5 В) на плате не выведен отдельной цепью — не задано в документах (на J6 вывод 1 есть +5V).
- U9 WS2812B-2020 (C965555): VDD = +5V (C18 100 нФ), DI ← GPIO48 `WS2812_DI` (RMT). Выход DOUT (вывод 1) не подключён. Согласования уровня 3.3 → 5 В на DI нет.

### 3.13 Отладка (J13, SW1, SW2)

J13 PH2.54-1×4 (C42431808): 1 = GND, 2 = +3V3, 3 = `UART0_TX` (GPIO43), 4 = `UART0_RX` (GPIO44). SW1 RESET (EN → GND), SW2 BOOT (GPIO0 → GND), оба TS263065A (C49023761). По расстановке v2 — у кромки y ≈ 1.5–4.4 мм рядом с ESC-гребёнками.

## 4. Питание

| Цепь | Откуда | Что питает | Элементы |
|---|---|---|---|
| `+5V_PWR` | J5 POWER, выводы 1, 2 (BEC модуля PWR, по ТЗ системы 5.3 В 3 А) | → D2 | дорожка 0.8 мм |
| `VBUS` | J2 USB-C | → D3; USBLC6 вывод 5 | дорожка 0.5 мм |
| `+5V` | диодное «ИЛИ» D2 + D3 (SS34, C8678) | U7, U8 (LDO), U6 VCC, U9 WS2812, разъёмы J6/J7/J8/J9 вывод 1 | TVS D4 SMAJ5.0A (C132575) +5V–GND; C11 10 мкФ, C12 100 нФ; дорожка 0.6 мм |
| `+3V3` | U7 XC6220B331MR-G (C86534), VIN = CE = +5V | модуль U1 (C1 10 мкФ, C2 100 нФ), R1/R2, J13, J6 вывод 8, подтяжки I2C и SD, C16, J1 VDD, U6 VIO, U10 VCC, D5 VCC; заливка на слое 16 | C13 10 мкФ; дорожка 0.5 мм |
| `+3V3S` | U8 XC6220B331MR-G, VIN = CE = +5V | только датчики U2, U3, U4, U5 и их развязки | C14 10 мкФ, C15 100 нФ; дорожка 0.4 мм |
| `+5V_SERVO` | внешний BEC через J12B | только J12B | не связана с +5V; дорожка 1.0 мм |

Особенности и расхождения с ТЗ:
- Оба LDO — одинаковые XC6220B331MR-G (README: «модуль ≥ 1 А, датчики»). Pinmap §3 предполагал для датчиков отдельный **малошумящий LDO 300 мА** — в схеме тот же XC6220. Пиковый ток модуля при Wi-Fi до 500 мА (ТЗ §2); ток передачи по атрибутам LCSC 355 мА.
- Защита входа: TVS SMAJ5.0A на +5V. Предохранителя и защиты от переполюсовки по 5 В в схеме нет (в ТЗ платы не требовались).
- Ориентация D2/D3: по `fc_esp32.py` A = +5V_PWR / VBUS, K = +5V; в Netlist вывод 1 = +5V, вывод 2 = источник — ориентацию катода по символу C8678 проверить перед заказом.
- ESD на входе питания (ТЗ §2 «ESD на входе») — только TVS D4.

## 5. Разъёмы и подключение

Все JST — JST-GH 1.25 мм (Pixhawk Connector Standard). «Снаружи» — что подключается, по `02_ТЗ_система.md` §6 и ТЗ платы.

### J5 — POWER (SM06B-GHS-TB, C133065), к модулю PWR

| Pin | Цепь | GPIO | Снаружи |
|---|---|---|---|

## 7. Прошивка

### 7.1 ArduPilot ESP32 — что известно по документам

- Официальный порт AP_HAL_ESP32 экспериментальный, нацелен на classic ESP32; S3 «в работе». Для S3 — сторонние форки (`esp32s3devkit`, Rover 4.6.3, ESP-IDF v5.3; IMU по I2C из-за PSRAM-пинов, без SD, консоль на UART, не на USB) — `B_esp32_fc.md` §2.1. У нас N16 без PSRAM, SPI свободен (ТЗ §1).
- Работает (по README порта и форуму): SPI/I2C датчики, u-blox GPS по UART, PWM-выходы (в порте 6, «работает 4»), Wi-Fi softAP + MAVLink TCP/UDP (SERIAL1 в порте — Wi-Fi, не физический UART), оба ядра.
- Не работает / не подтверждено: DShot (PR #33555/#33632/#33633, июль 2026, не слиты), SD-логи («монтируется, но логирование не работает»), CAN (драйвера нет), RC по CRSF/SBUS (порт использует PPM — не подтверждено), ADC частично, Copter на S3 (данные только по Rover), подавление газа при disarm.
- Нужен собственный hwdef в `libraries/AP_HAL_ESP32/boards/` по таблице §6 (SPI/I2C/UART/PWM номера пинов) — Pinmap §4. Перед разводкой/заказом проверить: слияние PR DShot, наличие таргета esp32s3 в master, SD-логи, Copter на S3 (ТЗ §4). Состояние на 25.11.2026 — не задано в документах (последняя проверка — июль 2026 по `B_esp32_fc.md`).
- Бюджет пинов порта: SERIAL0 консоль (UART0/USB), SERIAL1 Wi-Fi, UART1 GPS, UART2 RC — ESC-телеметрия и UART подвеса не помещаются (`B_esp32_fc.md` §4).

### 7.2 Как прошить

- **USB-C (J2)**: встроенный USB OTG на GPIO19/20 — CDC и прошивка (ТЗ §1 «OTG CDC + прошивка»). 
- **UART0 (J13)**: GND / 3V3 / TX GPIO43 / RX GPIO44 через внешний USB-UART.
- Кнопки: SW2 BOOT (GPIO0 на GND) и SW1 RESET (EN на GND). Стандартная для ESP32-S3 последовательность входа в загрузчик — удерживать BOOT и нажать RESET (в документах проекта процедура явно не описана).
- Инструменты на ПК Олега: ядро Arduino `esp32:esp32@4.0.0` установлено через `arduino-cli` (конфиг `C:\dev\arduino-cli-cfg`, `05` §5 — ставилось для ESP32-C3 наземного модуля); ESP-IDF — не задано в документах.

## 9. Известные расхождения и что проверить перед заказом

Из README («Расхождения и заметки»), ТЗ §5, Pinmap, `05` §6/§6.1, плюс найденное при сверке `fc_esp32.py` ↔ Netlist ↔ BOM в этом описании.

1. **GPIO33/34 не выведены у WROOM-1** → M4/M5/M6/M7 на IO35/36/37/46; M8 и SAFETY_LED отсутствуют. Таблица Pinmap §2 обновлена, но GPIO46 там указан дважды (PWM M7/AUX и SAFETY_LED) и текст «занято 32 GPIO» не совпадает с 34 в схеме — привести Pinmap к схеме.
2. **IO46 — strapping**: подтяжка 10 кОм на GND стоит (R11); сигнал использовать только как выход после старта; ESC на M7 при загрузке получит низкий уровень — приемлемо ли, не задано в документах.
3. **SBUS-инвертор U10**: выход RC_RX_INV ни к чему не подключён; для SBUS нужна перемычка RC_RX_INV → RC_RX (и, видимо, разрыв R12) — решить до заказа (`05` §6.1).
