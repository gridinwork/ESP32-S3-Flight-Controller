# 04. ТЗ на плату FC-ESP32 — экспериментальный полётный контроллер на ESP32-S3

Версия 0.1, 2026-11-21. Основание: `00 - ТЗ и система\research\B_esp32_fc.md`, `00 - ТЗ и система_ТЗ_система.md`, живая проверка LCSC 21.11.2026.

## 0. Главное решение: какой Espressif и зачем эта плата

**«ESP32-S5» не существует.** Актуальные чипы: ESP32 (classic), S2, S3, C3, C5, C6, C61, H2, P4.

| Чип | Ядра | UART | SDMMC (microSD 4 бит) | TWAI (CAN) | USB | Вывод |
|---|---|---|---|---|---|---|
| **ESP32-S3** | 2 × 240 МГц | 3 | есть | 1 | OTG | **единственный реалистичный кандидат**: есть наработки ArduPilot, SDMMC, два ядра |
| ESP32-C3 | 1 × 160 МГц RISC-V | 2 | нет | 1 | Serial-JTAG | мало GPIO (22), одно ядро — только как Wi-Fi-мост |
| ESP32-C5 | 1 × 240 МГц | 3 | нет | 2 | Serial-JTAG | Wi-Fi 6 на 5 ГГц интересен для видео/телеметрии, но порта ArduPilot нет, одно ядро |
| ESP32-C6 | 1 × 160 МГц | 3 | нет | 2 | Serial-JTAG | как C5, без 5 ГГц |
| ESP32-P4 | 2 × 400 МГц | 6 | есть | 3 | OTG HS | сильное железо, но без Wi-Fi (нужен C6 рядом) и без порта ArduPilot — задел на v2 |

Честная оценка: **паритета с Pixhawk 2.4.8 на ESP32 сегодня нет.** Порт ArduPilot на ESP32 официально экспериментальный; на S3 — сторонние форки: DShot только в открытых PR (июль 2026), SD-логи не работали, CAN нет, UART всего 3 (один из них консоль), детерминизм хуже из-за Wi-Fi-стека. На PWM-ESC квадрокоптер летает (Stabilize/AltHold/Loiter), телеметрия MAVLink по Wi-Fi работает «из коробки».

Поэтому FC-ESP32 проектируется как **экспериментальная плата и Wi-Fi-телеметрийный мост**, а не как основной контроллер коптера. Ценность: отладка порта ArduPilot ESP32, стенд для датчиков (те же IMU/баро/компас, что на FC-STM32 — результаты сравнимы), MAVLink по Wi-Fi на планшет без дополнительных модулей.

**Модуль: ESP32-S3-WROOM-1-N16 (без PSRAM)** — C2913199, 788 шт., 4.43 $/10. Без PSRAM освобождаются GPIO35–37 (у R8-версий они заняты Octal PSRAM). N16R8 на LCSC 0 шт., N8R8 — 2843 шт. (если понадобится PSRAM — не для этой задачи).

## 1. Функции (урезанный набор относительно FC-STM32)

| Функция | Реализация на S3 | Ограничение |
|---|---|---|
| IMU ×2 | SPI2 (FSPI): IIM-42652 + BMI270, общие SCK/MISO/MOSI, два CS, два INT | в S3-форке IMU по I2C из-за PSRAM-пинов — у нас N16, SPI свободен |
| Барометр | MS5611 на той же SPI (третий CS) | — |
| Компас встроенный | IST8310 на I2C0 | — |
| Внешний I2C (компас GPS) | I2C0, тот же разъём GPS 6 pin | один I2C на всё, адреса не должны конфликтовать (IST8310 0x0E, QMC5883L 0x0D, INA226 0x40) |
| GPS | UART1 | — |
| RC CRSF | UART2 | SBUS-инвертор 74LVC1G14 предусмотреть |
| Телеметрия | **Wi-Fi UDP/TCP** (SERIAL1 в порте) + UART0 как консоль/MAVLink по USB | физических UART под LoRa-телеметрию не остаётся — TLM-AIR подключать через UART2 вместо RC только в стендовом режиме, либо через ESP-NOW/Wi-Fi мост |
| ESC | 4–8 PWM (LEDC/MCPWM), DShot — после слияния PR в ArduPilot | 8 пинов |
| AUX | 2 PWM для подвеса | — |
| microSD | SDMMC 1 бит (CLK, CMD, D0) — 3 пина, чтобы уложиться в бюджет GPIO | 4 бит не влезает |
| Батарея | INA226 по I2C (от PWR) + 1 ADC (напряжение, делитель 11:1 на ADC1) | ADC ESP32 шумный — INA226 основной |
| USB | USB-C на USB_D+/D− (GPIO19/20): OTG CDC + прошивка | — |
| Отладка | UART0 на 4-pin 2.54 мм + кнопки BOOT/RESET | — |
| Зуммер, LED | 1 GPIO ключ + 1 WS2812 | — |

Бюджет пинов (N16, без PSRAM; доступно ≈ 33 GPIO без strapping-конфликтов): SPI 3 + CS 3 + INT 2 = 8; I2C 2; UART1 2; UART2 2; PWM 8; AUX 2; SD 3; USB 2; ADC 1; buzzer 1; WS2812 1; UART0 2 = 34. Впритык: при нехватке убрать INT второго IMU и один AUX. Таблицу пин-в-пин делать вместе с `hwdef` ESP32-таргета.

## 2. Питание

- 5 В от PWR/USB (диодное «или»), LDO 3.3 В ≥ 1 А для модуля (пики Wi-Fi до 500 мА) + отдельный LDO 3.3 В для датчиков. 10 µF + 100 нФ у пина 3V3 модуля, ESD на входе.
- Антенна модуля — за край платы, 15 мм без металла; GPS-антенна и ELRS-приёмник на раме не ближе 10 см.

## 3. Механика

50 × 50 мм, 30.5 × 30.5 мм отверстия, модуль у короткого края антенной наружу, IMU в центре, 4 слоя.

## 4. Прошивка

- ArduPilot ESP32 (ветка/форк с таргетом S3), собственный hwdef; проверить до разводки: состояние PR #33632/#33633 (DShot), наличие таргета esp32s3 в master, работу SD-логов, поддержку Copter (не только Rover) на S3.
- Запасной план, если ArduPilot на S3 не доводится: плата используется как Wi-Fi/ESP-NOW-мост телеметрии и стенд датчиков под свою прошивку (Arduino/ESP-IDF) — всё железо для этого на плате есть.
